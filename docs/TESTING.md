# Testing Strategy

## Hard safety release metrics

These are zero-tolerance competition gates:

- unauthorized mutations = **0**
- source/original mutations = **0**
- protected visible text changes = **0**
- false `VERIFIED` = **0**
- prompt-injection escape = **0**
- unsafe/unknown candidate execution = **0**

## Agent-depth gates

The planner is tested separately from the deterministic safety boundary.

- it may select only server-generated, already-simulated safe candidate IDs;
- it may never select two candidates for the same issue;
- it must obey `max_mutations`, `max_scale_factor`, and title protection;
- it must return `NO_FEASIBLE_PLAN` when the requested target coverage cannot be reached within constraints;
- a selected multi-issue plan is re-simulated as one combined artifact before approval;
- approval is bound to the exact ordered candidate list, source hash, candidate parameter/evidence snapshot, constraints, and combined-plan evidence fingerprint;
- final verification starts from the saved output artifact and checks every selected target independently.
- unrepairable below-target issues remain visible in `unresolved_issue_ids` rather than disappearing from aggregate coverage.
- candidate or combined-plan evidence tampering after planning invalidates approval;
- a new analysis revision invalidates any prior plan/approval/output before replacement evidence is computed;
- same-session analyze/plan/approve mutations are serialized by a per-session lock;
- source-byte tampering after upload is rejected immediately before execution;
- repeated rendered text in distinct shapes is bound by slide geometry rather than text alone, while overlapping ownership fails closed.

## v12 safety-oracle regressions

The release gate now includes explicit adversarial coverage for:

- text wrapping / overlap introduced by font scaling;
- analyzability loss that would otherwise inflate coverage;
- partial structural-to-rendered text reconstruction;
- image-only and outside-reference decks never becoming `NO_ACTION_REQUIRED`;
- unsupported table text remaining visible as unknown coverage;
- missing-font substitution and autofit remaining non-automatic;
- legal-XML-whitespace external relationships;
- zero-mutation planning when requested coverage is already satisfied;
- bounded candidate-simulation workload;
- `VERIFIED` requiring no remaining unknown/uncovered analysis condition.


## v13 package/runtime boundary regressions

The deterministic gate additionally proves that:

- a ZIP with a `.pptx` suffix but missing required OOXML presentation parts is rejected before session creation;
- non-canonical package paths such as dot-segment aliases are rejected;
- embedded OLE/ActiveX/package payloads are rejected in competition V1;
- an internal relationship that disguises an absolute URI (for example a `file:` target without `TargetMode=External`) is rejected, while normal parent-relative package relationships remain valid;
- per-entry decompression ratio, slide XML bytes, aggregate slide text characters, and text-run counts are bounded before LibreOffice is invoked;
- rendered PDF size and extracted rendered-text span count are bounded;
- the PyMuPDF document is closed even when the rendered-span budget is exceeded;
- a request queued behind a long-running session operation cannot enter after the session absolute TTL expires.

## Fixture policy

Development fixtures are project-owned and generated during the event. A separate holdout set has hand-authored expected outcomes and is not generated by production analysis code.

Resource/LibreOffice tests are intentionally executed in fresh pytest processes because repeated headless-office conversions can contaminate a long-lived renderer process. `scripts/release_gate.py` keeps mandatory round-trip gates isolated; stateful TestClient/LibreOffice approval guards are also isolated one-per-process in the full gate to avoid cross-case process-finalization contamination.


## Plan-integrity tests

- safe candidates without simulation fingerprints are non-executable;
- plan hashes change when candidate parameters change;
- plan hashes change when candidate simulation evidence changes;
- plan hashes change when combined-plan evidence changes;
- all below-target issue IDs remain part of planning context even when an issue has no safe candidate;
- approval returns conflict if any planned evidence changes after the plan was issued.


## v14 public-runtime regressions

The runtime/privacy gate adds explicit coverage for:

- no cross-session global-lock convoy while another session is queued;
- idle TTL leasing during long/queued operations and proactive no-request cleanup;
- marker-protected session-root cleanup and rejection of unowned/dangerous roots;
- private `0700`/`0600` session artifact permissions;
- separate session capability authorization (`X-Venue-Token`) with public IDs returning 404 without the token;
- browser refresh recovery strings and authenticated fetch/download flow;
- request-body limiting before multipart parsing, including chunked/no-Content-Length input;
- API/output `no-store` plus browser security headers;
- process-wide renderer concurrency bounding;
- renderer timeout terminating descendant processes;
- real-render deep readiness;
- single-worker deployment contract;
- bounded Gemini HTTP timeout and circuit-breaker fallback provenance;
- deterministic source-tree manifest evidence when `.git` metadata is unavailable.
